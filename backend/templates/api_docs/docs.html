协议文档

本服务同时提供网页界面与独立协议 API，两者行为完全一致。
基础地址：{{ base_url }}

鉴权

调用 /auth/login/ 或 /auth/register/ 获取 token，随后在每个请求头携带： 

Authorization: Bearer <token>

令牌有效期 7 天；网页端也可直接使用 Session Cookie。 未携带有效凭证时返回 401 与 JSON 错误体（不会跳转登录页）。

响应格式

所有接口统一返回 JSON：

// 成功
{ "ok": true, "data": { ... } }

// 失败（HTTP 状态码同时具有语义）
{ "ok": false, "error": { "code": "not_friends", "message": "需要先成为好友才能发起会话" } }

快速开始（curl）

# 1. 注册并拿到令牌
curl -s -X POST {{ base_url }}auth/register/ \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"secret123","nickname":"爱丽丝"}'

# 2. 之后的请求带上令牌
TOKEN=<上一步返回的 token>
curl -s {{ base_url }}auth/me/ -H "Authorization: Bearer $TOKEN"

# 3. 搜索用户 → 加好友 → 发起单聊
curl -s "{{ base_url }}users/search/?q=bob" -H "Authorization: Bearer $TOKEN"
curl -s -X POST {{ base_url }}friend-requests/ -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"user_id":2,"message":"你好"}'
curl -s -X POST {{ base_url }}conversations/ -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"type":"direct","peer_id":2}'

# 4. 发送消息（client_msg_id 用于幂等，重试不会重复发送）
curl -s -X POST {{ base_url }}conversations/1/messages/ -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"body":"你好呀","client_msg_id":"c-001"}'

# 5. 长轮询拉取新事件（cursor 单调递增）
curl -s -X POST {{ base_url }}updates/ -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"cursor":0,"timeout":25}'

账号

POST/auth/register/
注册。body: username、password、可选 nickname。返回 token 与用户信息。
POST/auth/login/
登录，支持用户名或昵称。返回 token。
POST/auth/logout/
撤销当前令牌并清除会话。
GET/auth/me/
当前用户信息。PATCH 可改昵称与个性签名。
POST/auth/password/
修改密码，成功后撤销全部旧令牌。
POST/auth/token/refresh/
换发新令牌（旧令牌立即失效）。
GET/users/search/?q=关键词
按用户名或昵称搜索，最多 20 条。
GET/users/<id>/
查看他人公开资料。

联系人

GET/friends/
好友列表，含在线状态。
DELETE/friends/<id>/
删除好友（双向解除，保留历史消息）。
GET/friend-requests/?direction=incoming|outgoing
好友申请列表。incoming 为收到的待处理申请。
POST/friend-requests/
发起申请。body: user_id、可选 message。若对方已向你发起申请则直接互为好友。
POST/friend-requests/<id>/accept|reject/
处理申请，仅收件人可操作。

会话

GET/conversations/
会话列表，含未读数、置顶/免打扰、最后一条消息摘要。
POST/conversations/
创建会话。{"type":"direct","peer_id":2} 幂等复用既有单聊（需先成为好友）；{"type":"group","title":"群名","member_ids":[2,3]} 建群。
GET/conversations/<id>/
会话详情与成员列表。
PATCH/conversations/<id>/
改群名（群主/管理员），或设置 is_muted、is_pinned。
POST/conversations/<id>/members/
添加成员（群聊，需管理员）。
DELETE/conversations/<id>/members/<uid>/
移除成员；移除自己即退出。
POST/conversations/<id>/leave/
退出会话。单聊退出将删除整段会话。
POST/conversations/<id>/read/
标记已读。body: {"up_to_seq":12}，省略则读到最新。
POST/conversations/<id>/typing/
上报「正在输入」，状态保留 5 秒。

消息

GET/conversations/<id>/messages/?before_seq=&after_seq=&limit=
拉取消息。after_seq 用于断线补齐（升序），before_seq 用于向上翻历史。
POST/conversations/<id>/messages/
发送消息。body: body、可选 attachment_id、reply_to_id、client_msg_id（幂等键）。
POST/messages/<id>/revoke/
撤回消息。限发送后 2 分钟内，发送者或群管理员可操作。

附件

POST/attachments/
上传附件，multipart/form-data，字段名 file，上限 20MB。图片自动生成缩略图并校验真实格式。
GET/attachments/<id>/download/?thumb=1
下载附件，仅上传者或所属会话成员可访问。

实时事件流（长轮询）

POST/updates/
请求 {"cursor":N,"timeout":{{ longpoll_timeout }}}；无新事件时挂起至多 {{ longpoll_timeout }} 秒，超时返回空数组。游标单调递增，保证不漏不重。
GET/presence/?user_ids=1,2
查询指定用户在线状态。

事件类型

type说明
message.new新消息，payload 为完整消息对象
message.revoked消息被撤回，payload.message 为脱敏后的消息
message.removed消息被管理员移除（正文与附件已清空）
read.receipt已读回执（单聊含 reader_id，群聊含 reader_count）
typing对方正在输入，payload.ttl 为有效秒数
conversation.updated会话信息变更（如群名）
friend.request收到好友申请
friend.accepted好友申请被同意
// 事件信封
{
  "event_id": 128,              // 同时作为下一次请求的 cursor
  "type": "message.new",
  "conversation_id": 7,
  "payload": { ... },
  "ts": "2026-01-01T12:00:00+08:00"
}

客户端能力声明

GET/capabilities/
无需鉴权。客户端据此选择连接方式与可用特性；登录/注册响应中也会返回同一份数据。
{
  "ok": true,
  "data": { "capabilities": {
    "api_version": "v1",
    "transport": ["longpoll"],      // 二期将追加 "websocket"
    "features": ["groups", "attachments", "read_receipts", "revoke",
                 "typing", "reports", "preferences", "global_search"]
  } }
}

管理接口（仅管理员）

以下端点要求账号具备 is_staff，否则返回 403。管理员界面 /manage/ 使用同一批接口。

方法路径说明
GET/ops/overview/用户/会话/消息统计与近 7 日趋势
GET / PATCH/ops/users/、/ops/users/<id>/用户列表；禁用/解禁（不能禁用自己）
POST/ops/users/<id>/revoke-tokens/强制下线该用户全部设备
GET/ops/conversations/、/ops/conversations/<id>/会话列表与详情（可读非本人会话，读取会记审计）
GET/ops/messages/跨会话消息检索
POST/ops/messages/<id>/remove/移除消息（清空正文并向成员广播）
GET/ops/reports/举报列表
POST/ops/reports/<id>/resolve|dismiss/处理举报（结案可选同时移除消息）
GET/ops/audit/管理员操作日志

其他

GET/healthz
无需鉴权的健康检查，只返回 ok、db、version；数据库异常时返回 503。
GET/search/?q=&type=all|message|user|conversation
全局搜索。消息搜索**仅限本人参与的会话**，绝不会返回他人会话内容。
POST/messages/<id>/report/
举报消息（仅记录，由管理员在 /manage/reports/ 判断处置）。
POST/users/me/avatar/
上传头像，服务端统一裁剪为 256×256 JPEG。
GET/users/me/preferences/
读取/更新用户偏好（PATCH），供网页端与 App 共享。

第二期：WebSocket 契约（已冻结）

二期将新增 WebSocket 通道。为避免届时再做决策，这里先冻结契约： 事件信封、字段语义、游标机制与长轮询完全相同， 客户端只需把「HTTP 请求循环」换成「WebSocket 消息处理」。

项约定
路径ws://<host>/ws/events/（TLS 下为 wss://）
鉴权优先 ?token=<访问令牌>；同源 Cookie 亦可
订阅连接后客户端发 {"type":"subscribe","cursor":N}；服务端回 {"type":"subscribed","cursor":M}
事件帧{"type":"event","event":<事件信封>}，信封字段与长轮询一致
心跳服务端每 25 秒发 {"type":"ping"}；客户端回 {"type":"pong"}，60 秒无响应即断开
断线续传重连后用 subscribe 携带最后收到的 event_id 作为 cursor，服务端补发期间事件
上报仍走 HTTP：POST /conversations/<id>/typing/、/read/、/messages/
错误{"type":"error","error":{"code","message"}}，错误码沿用 REST 的取值

前端已按此契约抽象出传输层（static/js/transport.js）： 二期新增 ws-transport.js 实现同一接口即可， 事件处理与界面代码不需要改动。后端切换点见 backend/realtime/registry.py。
